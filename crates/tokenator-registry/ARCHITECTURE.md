# tokenator-registry

JOSE/COSE/JWT/CWT claims and headers registry. See the top-level
`ARCHITECTURE.md` for its place in the workspace and `TEST-PLAN.md` for the
behaviour the tests pin down.

## Modules

| File | Role |
|---|---|
| `entry.rs` | `Entry`, `EntryKind`, `Label`, `Source`, `SpecRef`, `RegistryId` (serde: the snapshot/local-additions form) |
| `parse.rs` | `parse_iana` (streaming quick-xml parser) and `LocalAdditions` |
| `registry.rs` | `Registry`: index, lookups, snapshot (de)serialization, `build`, `merge_iana` |
| `annotate.rs` | `Annotator` trait (`&dyn` for `tokenator-edn`) and its impl for `Registry` |

The crate is I/O-free and builds for `wasm32-unknown-unknown`. Dependencies:
`quick-xml` (pure Rust), `serde`, `serde_json`.

## Data

- `data/local-additions.json` is hand-maintained: the pinned SD-CWT revision
  and codepoints the four IANA registries lack (SD-CWT tags/simple value,
  token-relevant CBOR tags, fallbacks for TEMPORARY registrations).
- `data/snapshot.json` is generated by `tools/registry-gen` and embedded with
  `include_bytes!`. It is JSON with one entry per line (diff-friendly, about
  156 KB, 20 KB gzipped). `Registry::shared()` parses it once (`OnceLock`) on
  first use; `Registry::bundled()` returns a fresh, mergeable copy.

## Model

- `Registry` keeps **all** entries sorted by (identity, precedence) plus a
  `BTreeMap<identity, index>` of the visible one per identity. Identity is
  `(kind, kty for COSE key type params, label)`; precedence is
  `Refreshed > Iana > Local`.
- Shadowing is not stored: a `Local` entry is hidden while a non-local entry
  has the same identity. So the snapshot just contains both, and a local entry
  resurfaces when a merge drops the IANA codepoint (expired TEMPORARY).
- `merge_iana` parses first (so errors leave the registry untouched), then
  replaces all non-local entries of `which.kinds()` with the refresh.
- The XML parser is iterative (no recursion), tracks depth to reject
  truncated documents, and only reads `<xref>` direct children of `<record>`
  as references; inline `<xref>`s in descriptions become text (`RFC 8392`).

## Annotation

COSE shows registered names (`1` → `alg`); JOSE shows descriptions, since the
key already is the name (issue #6). Values are annotated for header `alg`
(and COSE `sd_alg`, JOSE `enc`) and for key `kty`/`alg`/`crv`, chosen by the
*name* of the key's entry, so kty-specific labels (`-1` is `crv` for EC2 but
`n` for RSA) work without special cases.
